# 코드 품질 정책

## TypeScript

- 새 코드에서 `any` 사용을 피합니다.
- API 응답과 props에는 명시적인 타입을 정의합니다.
- 타입 단언은 사유가 분명한 경우에만 사용합니다.

## 검증 명령

변경 후 다음 명령을 실행합니다.

```bash
npm run build
npm run lint
npx prettier --check "src/**/*.{ts,tsx,css}" "*.{json,md,ts}"
```

## 컴포넌트 원칙

- 하나의 컴포넌트가 지나치게 많은 책임을 갖지 않게 합니다.
- API 요청과 화면 표시를 가능한 한 분리합니다.
- 컴포넌트 이름은 역할을 설명하도록 작성합니다.
- 접근성 속성과 키보드 조작을 고려합니다.
