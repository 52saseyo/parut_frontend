# Parut 화면 와이어프레임

이 문서는 현재 구현된 화면의 컨셉과 배치를 빠르게 확인하기 위한 텍스트 와이어프레임입니다. 실제 디자인 시안이 아니라, 백엔드 기능을 어느 화면에 어떤 정보 구조로 연결할지 설명하는 기준선입니다.

## 1. 고객 공통 레이아웃

```text
┌──────────────────────────────────────────────────────────┐
│ parut.       상품   타임딜   주문 내역       로그인  🛒    │  Header
├──────────────────────────────────────────────────────────┤
│                                                          │
│                    페이지 콘텐츠                          │
│                                                          │
├──────────────────────────────────────────────────────────┤
│ parut.  좋은 농수산물을 더 가까이, 파릇.                  │  Footer
└──────────────────────────────────────────────────────────┘
```

모바일에서는 상단 내비게이션을 줄이고 핵심 진입점과 장바구니를 우선합니다. 콘텐츠는 320px 이상에서 가로 스크롤이 생기지 않도록 합니다.

## 2. 홈 화면

```text
┌─────────────────────────────────────────────┐
│ parut.                         로그인  🛒    │
├─────────────────────────────────────────────┤
│                                             │
│  오늘의 식탁을                               │
│  파릇하게 채우는 방법        [추천 이미지]    │  Hero
│  [상품 둘러보기] [타임딜]                    │
│                                             │
├─────────────────────────────────────────────┤
│ LIMITED TIME                 전체 보기 →    │
│ [딜 카드] [딜 카드] [딜 카드]               │  핵심 발견 영역
├─────────────────────────────────────────────┤
│ PARUT PROMISE                               │
│ 산지에서 바로 | 알뜰하게 | 판매자와 성장      │
└─────────────────────────────────────────────┘
```

홈은 `products`, `time-deals` 데이터를 조합해 구성합니다. 첫 화면에서 서비스의 구매 가치와 타임딜 진입을 동시에 전달합니다.

## 3. 상품 목록

```text
┌─────────────────────────────────────────────┐
│ FRESH PRODUCTS                              │
│ 상품 둘러보기                  [정렬 ▾]       │
│ [전체] [채소] [과일] [곡물]                  │
├─────────────────────────────────────────────┤
│ [상품 이미지]  [상품 이미지]  [상품 이미지]   │
│ 상품명         상품명         상품명          │
│ 가격/단위      가격/단위      가격/단위       │
│                                             │
│ [상품 이미지]  [상품 이미지]  [상품 이미지]   │
└─────────────────────────────────────────────┘
```

상품 카드는 `ProductCard` 하나로 통일하고 상품 상태, 타임딜 여부, 가격, 판매자, 재고 정보를 조합합니다.

## 4. 상품 상세와 주문 진입

```text
┌─────────────────────┬───────────────────────┐
│                     │ 판매 중  타임딜        │
│                     │ 과일 · 파릇농원        │
│    상품 이미지       │ 논산 설향 딸기         │
│                     │ 12,900원              │
│                     │ ─────────────────     │
│                     │ 판매 단위    500g      │
│                     │ 남은 재고    24개      │
│                     │ 종료까지    02:18:42   │
│                     │ 수량  [−] 1 [+]        │
│                     │ [12,900원 주문하기]    │
└─────────────────────┴───────────────────────┘
```

상품 상세의 구매 버튼은 향후 `POST /api/v1/orders` 또는 타임딜 주문 API로 연결합니다. API 연결 전에도 수량 변경과 주문 확인 이동을 동작시킵니다.

## 5. 주문과 결제

```text
┌─────────────────────────────────────────────┐
│ CHECKOUT                                    │
│ 주문 확인                                    │
├────────────────────────────┬────────────────┤
│ 주문 상품                   │ 결제 요약       │
│ [이미지] 상품명  수량       │ 상품 금액       │
│                             │ 배송비          │
│ 배송 정보                  │ 총 결제 금액    │
│ [받는 분] [연락처]          │                │
│ [배송 주소              ]   │ [결제하기]      │
└────────────────────────────┴────────────────┘
```

결제 성공 후 주문 완료 상태를 보여주고 주문 목록으로 이동합니다. 실제 결제 연동 전에는 가짜 성공을 API 성공으로 간주하지 않고, UI 확인용 상태로만 사용합니다.

## 6. 주문 상세

```text
┌─────────────────────────────────────────────┐
│ 주문 상세                      배송 준비 중   │
│ P-20250918-001                              │
├────────────────────────────┬────────────────┤
│ 주문 상품                   │ 결제 금액       │
│ 상품명 / 수량 / 금액        │ 상품 금액       │
│                             │ 배송비          │
│ 배송 현황                   │ 총 결제         │
│ ● 주문 완료 — ● 상품 준비   │ [취소 요청]     │
│ ○ 배송 완료                 │                │
└────────────────────────────┴────────────────┘
```

주문 상태, 결제 상태, 배송 상태는 서로 다른 상태로 표시합니다. 백엔드의 `OrderStatus`, `PaymentStatus`, `DeliveryStatus`를 한 개의 상태로 합치지 않습니다.

## 7. 판매자 센터

```text
┌──────────────┬────────────────────────────────┐
│ Seller Center│ 판매자 대시보드                 │
│              │                                │
│ 대시보드     │ [이번 달 주문] [판매 상품]       │
│ 상품 관리    │ [배송 대기]   [이번 달 정산]     │
│ 재고 관리    │                                │
│ 주문·배송    │ 최근 업무                       │
│ 정산         │ 상품 / 재고 / 주문 테이블        │
└──────────────┴────────────────────────────────┘
```

판매자 화면은 고객용 헤더와 분리된 업무용 사이드바를 사용합니다. 상품·재고·주문은 테이블을 기본으로 하되 모바일에서는 가로 스크롤과 핵심 열 우선 표시를 적용합니다.

## 8. 관리자 콘솔

```text
┌──────────────┬────────────────────────────────┐
│ Admin Console│ 운영 대시보드                   │
│              │ [전체 회원] [승인 대기]           │
│ 운영 대시보드│ [오늘 주문] [환불 요청]           │
│ 판매자 승인  │                                │
│ 상품 운영    │ 승인 대기 판매자 목록             │
│ 주문·환불    │ [판매자] [상태] [승인] [검토]      │
│ 재고 운영    │                                │
│ 정산 운영    │                                │
└──────────────┴────────────────────────────────┘
```

관리자 화면은 고객·판매자 화면과 시각적으로 구분하되 같은 상태 배지와 테이블 규칙을 재사용합니다.

## 9. 디자인 토큰

| 용도    | 색상 방향           | 사용 예                     |
| ------- | ------------------- | --------------------------- |
| Primary | emerald             | 구매, 저장, 승인, 정상 상태 |
| Accent  | orange              | 할인, 타임딜, 처리 필요     |

| Danger  | red                 | 오류, 취소, 거절            |

## 10. 구현 원칙

- 화면에서 보이는 버튼은 실제 API가 연결되기 전에도 이동 또는 상태 변화가 있어야 합니다.
- API 연결 시 목업 배열을 query hook의 결과로 교체하되 화면 컴포넌트의 정보 구조는 유지합니다.
- 역할별 화면은 공통 `StatusBadge`, `DataTable`, `EmptyState`를 재사용합니다.
- 모든 주요 흐름에는 성공·실패·빈 상태를 추가합니다.
